# Phase 2: Universal Hashing (Carter-Wegman Mitigation)

This directory contains the implementation of **Universal Hashing**, specifically based on the Carter-Wegman construction, designed to completely mitigate hash flooding denial-of-service attacks.

## The Core Concept

In a standard, deterministic hash table, an attacker with knowledge of the hash algorithm can compute keys that map to the same bucket (collisions) offline. If they send a massive payload of these colliding keys, the application's insertion and lookup times degrade to $O(N)$, causing severe CPU starvation.

Universal hashing solves this by selecting a hash function at random from a carefully constructed family of functions (a universal family) at runtime. Because the specific hash function parameters (often prime numbers and random seeds) are initialized when the hash table is created and kept secret from the attacker, it becomes probabilistically impossible for the attacker to pre-calculate collisions. 

## Included Files

*   **`carter_wegman.c`** / **`hash_table_cw.c`**: The core C implementations of the randomized hash family and the protected data structure.
*   **`fuzzer.py`**: A Python-based fuzzing utility designed to generate and inject payloads into the hash table to test its resilience.
*   **`fuzzer_target.c`**: The C harness that compiles the hash table and receives input from the fuzzer.
*   **`fuzzer_before_bulk.log`** & **`fuzzer_after_bulk.log`**: Logs capturing the behavior, CPU time, and collision rates before and after applying bulk randomized payloads.

## Architecture & Scope of Testing

To properly test the resilience of the universal hashing implementation, `fuzzer_target.c` acts as a bridge. It reads payloads generated by `fuzzer.py` and feeds them into the `hash_table_cw.c` data structure.

**Testing Disclaimer:** The standard input parsing operations used within `fuzzer_target.c` to read the fuzzer's payload stream are intended purely for local stress testing. The use of basic stream reading functions in this context is intentional to maximize payload throughput from the Python script to the C executable. These I/O handlers are not part of the Carter-Wegman algorithm and are not intended for production-facing network input parsing.

## How to Run the Fuzzer

1. Compile the target harness:
   `gcc -O2 fuzzer_target.c -o fuzzer_target`
2. Run the fuzzer script to pipe data into the target:
   `python3 fuzzer.py`

Analyze the logs to observe how the randomized parameters effectively distribute the payload evenly across the buckets, maintaining $O(1)$ amortized time complexity even under a deliberate attack attempt.
