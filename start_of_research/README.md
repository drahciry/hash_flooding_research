# Phase 1: The Vulnerability (Hash Flooding)

This directory contains the foundational research on how standard hash tables fail under adversarial conditions. 

When a hash function is deterministic and its internal state is known (or easily guessed), an attacker can precompute thousands of strings that map to the exact same bucket index. In a hash table using Separate Chaining, this turns an $O(1)$ lookup into an $O(N)$ linked-list traversal, effectively choking the CPU and causing an algorithmic Denial of Service (DoS).

## Contents
* **`hash_table_dh.c` / `hash_table_dh_old.c`**: Target implementations using standard, predictable hashing algorithms.
* **`generate_collisions.py`**: The offensive script. It exploits the mathematical properties of the deterministic hash to forge a massive payload of colliding keys.
* **`collisions.txt`**: A sample payload generated by the Python script, ready to be piped into the C targets.

## Usage
To witness the CPU degradation, compile the C target and pipe the collision payloads into it:
```bash
gcc -O2 hash_table_dh.c -o vulnerable_table
cat collisions.txt | ./vulnerable_table
